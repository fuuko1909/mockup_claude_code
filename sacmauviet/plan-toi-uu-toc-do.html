3. Kế hoạch

Giai đoạn 1 — Sửa nhanh, tác động lớn (~1 ngày, chỉ frontend)

Việc Cách làm Ước tính
B Bỏ tải lại trang với khách mới CacheBuster: chỉ reload khi thực sự có service worker cũ / cache cũ; khách mới chỉ ghi khoá phiên bản 15 phút
D Cache session ở apiClient Ghi nhớ kết quả getSession() ~30 s (dùng chung 1 promise khi nhiều request song song); xoá khi đăng nhập/đăng xuất/401 45 phút + test
A Ảnh qua /_next/image Helper anhToiUu(url, rong) dùng lại bộ tối ưu sẵn có (AVIF/WebP, đã cấu hình images trong next.config.ts); áp cho: thẻ danh mục, quạt ảnh hero, SanPhamCard, CarouselStrip, FeatureColumns, PromoBlocks, BannerNho, thumbnail mẫu (file-asset), giỏ hàng, gallery sản phẩm. Thêm loading="lazy" + sizes; ảnh LCP đầu trang fetchpriority="high" 3–4 giờ
F Giữ chỗ chống xô lệch aspect-ratio cố định cho khung preview sản phẩm, ảnh gallery, logo; kiểm tra lại CLS đăng nhập (nghi popup/thông báo chèn vào) 1–2 giờ

Kỳ vọng: trang chủ 4,4 MB → ~0,7 MB, LCP lab 15 s → ~3 s; khách mới không còn tải 2 lần; bớt ~13 request/trang.

Giai đoạn 2 — Cloudflare (cần bạn: quyền dashboard hoặc API token)

Việc Cài đặt
C1 Tôn trọng header cache của origin Caching → Configuration → Browser Cache TTL = "Respect Existing Headers"
C2 Cache ở edge (gần khách VN) Cache Rules: /_next/static/*, /_next/image*, /brand/*, /img/*, font → Eligible for cache, Edge TTL theo header origin; /api/v1/cms-anh/*/file → cache 1 ngày
C3 Không cache HTML / API động Giữ mặc định (đang no-store)

Kỳ vọng: file tĩnh trả từ edge Cloudflare (thường < 50 ms ở VN) thay vì về VPS; khách quay lại không tải lại JS/font.

Đổi cấu hình dịch vụ ngoài → mình không tự làm. Bạn cấp API token Cloudflare (quyền Zone → Cache Rules + Zone Settings, chỉ zone insacmauviet.vn) hoặc mình gửi hướng dẫn từng bước để bạn bấm.

Giai đoạn 3 — Trang sản phẩm nhẹ lại (~1 ngày)

Việc Cách làm
E1 Hiện ảnh preview tĩnh trước Lần đầu mở: ảnh render sẵn của mẫu (đã có hinh_anh_url / thumbnail) qua /_next/image; chỉ tải Konva + preview tương tác khi khách bấm "Tuỳ chỉnh" hoặc sau khi trang rảnh (requestIdleCallback)
E2 Font mẫu tải theo nhu cầu Chỉ tải font của trường đang hiển thị / đang sửa; dùng bản subset web (backend đã có cờ subset — migration 0071) thay font đủ; font-display: swap
E3 Tách bundle dynamic(() => import(...), { ssr: false }) cho InteractiveTemplatePreview, BasicEditPanel, MockupPreview; kiểm tra lại JS route (366 KB → mục tiêu < 200 KB)

Kỳ vọng: TBT 3,3 s → < 600 ms, điểm 17 → 60+.

Giai đoạn 4 — Font giao diện + dọn nhỏ (~2 giờ)

  • Preload 2 file font chính (400 + 600, bộ vietnamese + latin); cân nhắc bỏ độ đậm 500 (map font-medium → 600 hoặc 400) — giảm ~25% byte font.
  • Bỏ request thừa: /api/version gọi 2 lần, /api/v1/cau-hinh-website gọi nhiều nơi → dùng chung react-query key.

Giai đoạn 5 — Ảnh gốc nhẹ từ đầu (tuỳ chọn, backend + dữ liệu)

  • Khi admin tải ảnh CMS: tự resize tối đa 2.000px + nén WebP; script một lần nén lại ảnh cũ trong MinIO (giữ bản gốc).
  • Chỉ cần nếu sau GĐ1+2 vẫn thấy ảnh gốc bị tải (vd. link ảnh dùng ngoài web). Đụng dữ liệu prod → hỏi trước.

4. Đo lại & chống thoái lui

  • Script đo (Playwright: dung lượng, request, ảnh quá cỡ, LCP/TTFB) + Lighthouse 3 trang → chạy trước/sau mỗi giai đoạn, ghi bảng vào file này.
  • Mục tiêu (Lighthouse mobile): / ≥ 85, /san-pham/[slug] ≥ 60, /dang-nhap ≥ 85; CLS < 0,1; trang chủ < 1 MB.
  • Quy ước mới: ảnh nội dung luôn qua helper anhToiUu (ghi vào CLAUDE.md mục cạm bẫy).
